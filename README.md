# 抖音 / 小红书 / 微博 内容批量下载工具

一款面向博主归档的批量下载工具，支持抖音、小红书与微博：在本地浏览器界面粘贴博主主页链接，即可自动翻页抓取作品并下载视频与图片，按发布时间命名、按类型分目录归档。

## 功能特性

**使用体验**

- **浏览器图形界面**：本地启动 Web 服务并自动打开浏览器（默认 `http://127.0.0.1:5000`），粘贴链接即可抓取下载，无需命令行
- **多平台合一**：抖音、小红书、微博共用一套界面与目录结构，博主列表按平台分组，可用下拉框筛选；新增平台只需补平台实现
- **多链接批量抓取**：输入框支持一次粘贴多个链接（换行、空格、中英文逗号/分号/顿号都可分隔），自动去重后串行执行，单条失败不影响后续
- **一键更新**：抓取过的博主会记住主页链接，之后点「更新」即可增量补全；也可按平台批量更新全部博主
- **关注列表批量下载**：读取本机已登录账号的关注列表，勾选想下的博主后一次性加入队列（当前支持抖音，其他平台的接口已预留）
- **作品预览**：点击博主行即可在右侧预览，默认显示图片，可切到视频；支持缩略图懒加载、视频封面取帧、大图/视频灯箱（键盘 `←` `→` 切换、`Esc` 关闭）
- **任务实时反馈**：阶段/状态文案、博主名、日志、失败列表（可一键复制失败 URL）实时刷新，任务可随时取消；不显示进度条

**下载质量与可靠性**

- **自动分类**：视频落在博主目录根，图片落在 `picture/`
- **时间命名**：以发布时间为文件名（`2026-01-01 10.00.00.mp4` / `2026-01-01 10.00.00 - 1.webp`），方便排序管理
- **原始画质**：抖音图片保留原始 WebP，小红书图片还原无水印原图，微博图片取 `large` 原图、视频取最高可用清晰度
- **断点续传 / 去重**：按作品 ID 记录（抖音 `aweme_id` / 小红书 `note_id` / 微博 `mblog_id`），一篇的全部媒体成功才记录，重复抓取只补新增
- **按篇一致性**：一篇里任一媒体失败则整篇不记录，下次整篇重下（同名覆盖），保证「有记录 = 这一篇完整」
- **扩展名探测**：下载先落 `.part`，完成后按响应头 → 文件头 → URL 后缀确定真实格式与落盘目录，CDN 地址不带后缀也能正确落盘
- **类型可配**：抖音按 `aweme_type` 分类（配置可改），未知类型跳过并在日志汇总提示
- **UTF-8 编码**：源码、日志、主页链接与 ID 记录全部以 UTF-8 读写

**安全边界**

- 服务只监听 `127.0.0.1`，不对局域网/外网开放
- 预览与媒体接口只允许读取下载根目录内的文件（路径越界一律 404）
- 同一时刻只允许一个任务；任务内流式逐篇（抓到一篇立即下载下一篇），批量更新也是逐条串行

## 下载目录布局

下载根目录由 `conf/config.ini` 的 `[download] download_dir` 决定，与代码目录无关：

```
{download_dir}/
├── douyin/                        # 平台目录（平台 key）
│   └── {博主名称}/                # 目录名即博主名，目录本身就是博主列表
│       ├── homepage.txt           # 主页链接（抓取成功后写入，供「更新」使用）
│       ├── aweme_id.txt           # 已下载作品 ID（一篇一行，创建博主目录时生成）
│       ├── {发布时间}.mp4          # 视频，如 2026-01-01 10.00.00.mp4
│       ├── picture/               # 图片目录（有图片作品时才创建）
│       │   └── {发布时间} - {序号}.webp
│       └── .cache/                # 预览缓存（可随时删除，会自动重建）
│           ├── thumbs/            # 图片缩略图
│           └── covers/            # 视频封面
├── xiaohongshu/                   # 结构同上，图片可能是 jpg/webp/avif/gif，HEIC 转 jpg
└── weibo/                         # 结构同上，图片为 large 原图，通常为 jpg
```

说明：

- 下载根目录不存在时自动创建；创建失败（盘符不存在、无权限等）程序报错退出
- 相对路径按**启动程序时所在的工作目录**解析，换目录启动会指向不同位置，建议直接写绝对路径
- 每个博主一个目录 `{download_dir}/{平台 key}/{博主名}/`，不存在时自动创建
- 平台目录下的一级子目录中，含 `homepage.txt`、`picture/` 或有视频文件才算博主；零散文件与 `.cache/` 等隐藏目录会被忽略
- 目录结构只由 `core/paths.py` 计算与提供：博主目录、图片目录、缓存目录、落盘路径与「这是不是缓存文件」的判定都由它给出，其它模块不拼目录、不接收目录参数
- 把已有的博主目录整个拷进对应平台目录，重启后界面即可识别并预览（缺 `homepage.txt` 时「更新」按钮不可用）
- 从旧版本升级：把 `download_dir` 的末尾去掉一级平台目录即可（例如原来填 `F:/图片/douyin/`，改为 `F:/图片/`），原有博主目录会直接成为平台目录，无需移动文件

## 快速开始

```bash
pip install -r requirements.txt
playwright install chromium      # 一键抓取需要，下载浏览器内核
python web_app.py
```

启动后控制台会打印实际下载目录与 Web 地址，并自动打开浏览器（端口被占用时按 `port_range` 向后顺延）。

- 缺少 Flask 时启动直接提示安装依赖
- 未安装 Playwright 时界面仍可浏览已下载内容，但「下载」「更新」按钮会被禁用

## 使用说明

页面分左右两块：左侧是「下载」与「博主管理」，右侧是「预览」。

### 下载

1. 标题右侧下拉框选「链接下载」，粘贴博主主页链接（可一次粘贴多个，每行一个；也可用空格/中英文逗号/分号/顿号分隔，自动去重）
2. 选择「全部作品」或「最近一个月」
3. 点「下载」，或按 `Ctrl/⌘ + Enter` 提交
4. 界面只显示任务阶段/状态文案、博主名与日志（逐篇「正在下载」），不显示进度条；发现下载失败时展开「下载失败」列表，可一键复制失败 URL

支持三种链接：

- 抖音：`https://www.douyin.com/user/MS4w...`（也接受裸 `sec_user_id`、带 `sec_user_id=` 的接口地址）
- 小红书：`https://www.xiaohongshu.com/user/profile/<24位id>?xsec_token=...`（**建议带上 `xsec_token`**，否则可能看不到内容；也接受裸 24 位 id）
- 微博：`https://m.weibo.cn/u/<uid>`（也接受 `https://weibo.com/u/<uid>`、卡片接口地址与裸 uid）

每条链接按域名自动识别平台。多条链接串行执行：前一条完成后才提交下一条，单条失败记录后继续。

### 博主预览

- 博主列表按平台分组，顶部下拉框可按平台筛选，选中博主行会高亮
- 点击博主行打开预览，默认「图片」，可在顶部切到「视频」，也可点「刷新」重新读取
- 图片缩略图按需生成并缓存；视频封面由前端取首帧后回存 `.cache/covers`，下次直接复用
- 点缩略图进入灯箱：图片按原图加载，视频自动播放（初始音量 20%），支持 `←` `→` 切换、`Esc` 关闭，鼠标移到左右边缘出现切换按钮

### 一键更新

抓取成功后，程序会把该博主的主页链接写入 `{download_dir}/{平台 key}/{博主名}/homepage.txt`。之后在「博主管理」里点该博主的「更新」，就会直接读这个链接重新抓取，不用再粘贴：

- 更新按「全部作品」抓取，能补上历史漏项
- 已下载的作品由 `aweme_id.txt` 里的作品 ID（抖音 `aweme_id` / 小红书 `note_id` / 微博 `mblog_id`）跳过，只下载新增内容
- 小红书会在取详情前就排除已下载的笔记（按主页链接里的 `user_id` 反查，连详情页都不打开）；抖音与微博在流式逐篇处理时按篇 ID 统一跳过
- 界面不显示进度条；任务收口时一次性写入 `done` / `total` 等快照统计字段，仅供接口兼容，不逐文件刷新
- 目录里没有 `homepage.txt`（例如手动拷入的目录）时按钮为禁用状态，重新粘贴一次链接抓取即可生成

### 批量更新

「博主管理」右上角的「更新」按钮按下拉框所选平台批量更新该平台全部博主（选「全部平台」时逐个平台跑）：

- 只更新登记过 `homepage.txt` 的博主，队列由前端串行提交，单个博主失败或没有新增内容都不影响后续
- 执行前弹确认框显示博主数量；任务可随时取消，取消后队列清空
- 整批共用一块日志框，结束时汇总「已完成 N 位，失败 M 位」并刷新列表

### 关注列表批量下载

「下载」卡片标题右侧的下拉框可切换两种下载方式：**链接下载**（粘贴主页链接）和**关注列表下载**。后者由「获取我的关注」读取本机浏览器数据目录里**已登录账号**的关注列表（当前支持抖音，不支持的平台不会出现在模式下拉里）：

- 关注列表只读取博主链接，不下载任何内容；抓完点「关注列表（N）」展开浮层勾选（浮层绝对定位，不占页面高度），再点同一个「下载」按钮入队
- 已下载过的博主标「已下载」且默认不勾，避免重复排队；「全选」只作用于清单里的博主
- 入队后复用批量抓取：逐位博主串行执行，单条失败不中断，结束时汇总「已完成 N 位，失败 M 位」
- 抓取范围按上方的「全部作品 / 最近一个月」执行；已下载的作品仍由 `aweme_id.txt` 去重
- 关注列表只有登录后才可见：首次使用需把对应平台段的 `headless` 改为 `false` 扫码登录
- 新增平台支持时只需实现 `Platform.following()` 并把 `supports_following` 置为 `True`，路由与界面自动生效

## 抓取说明（通用）

### 登录闸门

打开主页后先只做登录检测，**登录成立之前不注册响应监听、不读页面状态、不发任何数据请求，也不取任何条目**：

- 登录态按平台隔离，统一放在 `.pw_profile/` 下的平台子目录（可用 `conf/config.ini` 对应平台段的 `profile_dir` 改），**每个平台只需扫码登录一次**，之后无头运行即可
- 首次使用或登录失效时，程序会等待最多 `wait_login_seconds` 秒（默认 180），期间在弹出的浏览器窗口里扫码；`headless = true` 时窗口不可见，首次登录需先改成 `false`
- 登录态只认程序自己的浏览器数据目录（自己平时浏览器里的登录**无效**）；微博还会以接口返回的 `data.login` 复核
- 等待超时仍未登录：任务进入 `error`，按「未登录 <平台>：请在浏览器窗口完成登录后重试（登录态保存在 <profile_dir>）」提示，**一篇都不下载**；用户取消则任务为 `cancelled`
- 登录成功后强制刷新一次页面，丢弃登录前可能累积的响应与条目；刷新完成后才挂响应监听 / 读页面状态 / 发接口请求

### 身份信息单点获取

打开网页、过登录闸门并刷新后，由平台从**页面级数据**一次性取平台 key、平台显示名、博主名、博主 ID 与主页链接，交 `DownloadSession.meta()` 冻结为整个任务共享的一份内存数据：

- 唯一构造点是 `core/session.py` 的 `IDENTITY_FIELDS` 与 `identity()`；`Task.set_identity()` 只做投影，平台只回报原始三元组
- 来源按平台固定优先级（昵称与 ID 任一取不到即 `error` 并中止，不下载任何内容）：
  - 抖音：页面状态里的用户对象 → 主页昵称 DOM → `page.title()` 去掉 ` - 抖音` 后缀 → 空；ID 用 `parse_sec_user_id(target)`
  - 微博：页面内用户配置或主页昵称 DOM → `page.title()` 按 `的微博` 截断 → `page.title()` 原文 → 空；ID 用 `parse_uid(target)`
  - 小红书：`__INITIAL_STATE__.user` 下的基本信息 → 主页昵称 DOM → `page.title()` 按 ` - ` 截断 → 空；ID 用 `parse_user_id(target)`
- **只从页面自身取，不遍历作品/笔记/微博条目取作者名**；作者过滤使用冻结后的博主名，一次任务只对应一个博主目录
- 身份信息**只在内存里传递，不新增文件、不落盘**（浏览器登录态仍在 `.pw_profile/<平台 key>`）；`blogger_id` 不参与目录定位，目录名仍是博主名

### 其余约定

- 同一时刻只允许一个任务；抓到一条可处理条目就立即流式下载，当前篇完成后再取下一篇（下载层内部多地址并发），不再「先抓完再下载」
- 抓取范围选「最近一个月」时，连续遇到 12 条早于截止时间的作品就提前停止翻页
- 作者与目标博主不一致的作品（合作、改名、接口异常）会被丢弃，并在日志汇总提示，保证一次任务只对应一个博主目录
- 同一发布时间前缀被不同篇占用时会提示「本次将被覆盖」（文件名精确到秒，撞名概率很低）
- 未知 `aweme_type` 的作品会被跳过并在日志汇总提示，需要下载时把它加进 `conf/config.ini` 的 `[platforms.douyin]` 下 `image_types` / `video_types` 后重跑

## 抖音说明

- 不手工构造 `a_bogus` / `msToken` 等签名，全部交给真实浏览器生成：监听 `/aweme/v1/web/aweme/post/` 的响应体拿原始 JSON，滚动到底触发翻页，直到 `has_more = 0`
- 响应监听与首屏等待都放在登录闸门之后：未登录先等待扫码并中止取数，登录成功后强制刷新主页再从刷新后的页面翻页（不再有「匿名只给首屏一页」的兜底）
- 类型判定按 `aweme_type`（`image_types` / `video_types` 可配）；图片取每张 `url_list` 的第一个地址，视频取 `play_addr.url_list` 的第一个（同一文件的其余地址是备用 CDN，不能都下）
- 采集时按 `aweme_id` 去重，滚动容器逐层推进；连续 `idle_rounds` 次无新增即停止
- **关注列表**：不手工构造请求，打开 `https://www.douyin.com/user/self?showTab=following` 后监听 `/aweme/v1/web/user/following/list/` 的响应体，滚动触发翻页；接口一直没响应时退化为扫描页面上的用户链接

## 小红书说明

- 主页首屏约 60 条由页面状态下发（SSR，不发列表请求）；先过登录闸门并刷新，再读 `__INITIAL_STATE__` 与后续分页，登录前的匿名首屏一律丢弃
- 列表只用于发现笔记；每一条都打开详情取完整数据，**下载与命名一律用详情**，不与列表数据合并
- 取不到详情（没有 `xsec_token`、详情页打不开）的笔记直接丢弃，不拿列表数据凑数
- 已下载过的笔记在取详情前就跳过，不打开详情页（按主页链接里的 `user_id` 反查 `aweme_id.txt`）
- 详情接口的响应一到就立刻返回，不按固定间隔轮询；页面加载超时取 `timeout_ms`，等响应最多再多等 3 秒
- 判定规则：图片全部带实况标记 → 按图片；有视频流且只剩 1 张图 → 按视频；多图带视频流是平台合成的轮播视频，仍按图片只下原图
- 图片会还原成无水印原图（`sns-img-qc` 寻址，去掉展示链路的 `!` 压缩后缀）；扩展名由下载层按响应头/文件头探测
- HEIC 图片落盘后转成 JPG（`quality=98`、无色度抽样，转换失败保留原件；依赖 `pillow-heif`）
- 链接里的 `xsec_token` 会过期，过期后详情打不开，重新复制一次主页链接即可

## 微博说明

- **图片**：取 `mblog.pics[].large.url`（缺失时回退 `bmiddle` / `thumbnail` / 顶层 `url`），落成 `picture/{发布时间} - {序号}.{扩展名}`。微博的图片水印与分辨率实测不可兼得：`large` / `original` 是同一份 4032×2688 原图但带博主角标，`oslarge` / `osj1080` 无水印但最长边固定 690（图床忽略自定义尺寸参数），因此固定取 `large`，保住最高画质
- **视频**：按 `page_info` 取一个清晰度落成 `{发布时间}.mp4`。视频角标（@昵称 + 微博视频）是微博转码时烧录进画面的，所有直链都带，无法通过改地址去水印；要干净原片只能走作者开启下载权限时的 App「保存到相册」，或视频本身来自外链时去原平台取
- **视频取址**：先看 `page_info.urls`（`mp4_1080p_mp4` → `mp4_720p_mp4` → `mp4_hd_mp4` → `mp4_hd_url`），再按 `quality_level` 取 `media_info.playback_list` 里的地址，最后退到 `page_info.media_info.stream_url_hd` → `stream_url` → 标清；一条视频只下一个文件，`m3u8` 播放列表直接忽略（落盘只会得到文本）
- **类型判定**：微博没有抖音那种单一 `aweme_type`，按字段组合判断——`page_info.type` / `object_type` 为 `video`（或带 `media_info`）算视频，且先于图片判断（视频微博的 `pics` 只是封面图）；`pics` 非空算图片；两者都没有的（纯文字、头条文章、转发他人内容）跳过，并在日志里汇总提示跳过几篇
- 只处理微博自身的 `pics` / `page_info`：转发的他人内容不计入（外层没有媒体时按「无内容」跳过），Live 图只取其中的静态图片文件，不处理动态视频部分
- 抓取不靠滚动页面：登录后直接请求 `m.weibo.cn/api/container/getIndex` 卡片接口，按 `since_id` 翻页，每页间隔 1~2 秒；`card_type != 9`（分组、广告、推荐）自动跳过
- 首次使用需在弹出的浏览器窗口扫码登录（`headless` 必须为 `false`）；登录态存进 `.pw_profile/weibo/`，之后可无头运行
- 登录态以 `m.weibo.cn/api/config` 的 `data.login` 为准：匿名访客的 Cookie 里同样有 `SUB`/`SUBP`，只看 Cookie 名会把游客当已登录，因此未登录会直接中止并提示扫码
- Cookie 失效或触发风控时接口返回 `ok=0`，程序会直接报错提示重新登录，不会静默返回「没有内容」；但翻到最后一页时接口同样返回 `ok=0`（`msg` 为「这里还没有内容」），这属于正常的结束信号，按抓取完成处理、不报错；抓完第一页还会复核一次登录态，中途掉登录同样中止，不下载残缺数据
- 不显示进度条，快照里的 `done` / `total` 只在任务收口时写一次；去重仍按篇
- 去重按微博 ID（`mblog_id`）：一条微博的全部媒体成功才记录，任一个失败则整条不记录，下次整条重下，与抖音、小红书一致
- 翻页上限复用 `[platforms.default]` 的 `max_scroll`（微博按「翻页次数」使用，每页约 10 条），防止接口异常时死循环；选「最近一个月」时翻到时间边界会提前停止

## 项目架构

项目按「公用层 + 平台实现层」组织：公用层只写机制（任务、会话、编排、存储、命名、浏览器、单篇下载、媒体），平台层写规则（链接识别、登录闸门、页面身份获取、条目发现、类型判定、取地址、归一化）。

关键约定：**统一流式契约**。`platform.scrape_stream(target, options, session, ...)` 负责打开网页 → 登录闸门 → 刷新 → 一次性上报身份 → 逐条交出归一化 article；`DownloadSession` 负责冻结身份、逐篇调用 `downloader.fetch_article()`、统计与收口。article 只含 `id` / `create_time` / `urls` / `kind`，作者过滤已在平台层用冻结昵称完成；身份与 `store` 目标只在内存里传递，不新增文件。

### 下载流程

一次任务是**流式逐篇**处理，不再「先抓完再下载」：

1. `platform.scrape_stream(target, options, session, ...)` —— 打开网页 → 登录闸门（未登录等待、超时中止、登录前不取数据）→ 登录成功后强制刷新 → 从页面级数据取身份 → `session.meta(info)` 一次性冻结 → 翻页/取详情时逐条交出归一化 article（`id` / `create_time` / `urls` / `kind`）
2. `DownloadSession.article(article)` —— 立即调用 `downloader.fetch_article()` 处理该篇，按 `{发布时间}.mp4` / `picture/{发布时间} - {序号}.{扩展名}` 落盘；这篇处理完成后采集器才继续取下一篇
3. 结束由 `pipeline.run()` 收口：按统计与 `stop_flag` 一次性判定状态，写 `done` / `total` / 失败清单与 `finished` 事件

编排层在 `session.meta()` 里把本次目标登记给 `store`（`activate`，`session.close()` 里幂等 `clear`），落盘路径由 `store` 现算。下载层只判断「视频还是图片」，向 `store` 要路径——既不接收博主对象，也不接收任何目录参数。一篇内的媒体地址交给线程池（`[download] workers`，默认 1 表示逐个下载），全部成功才把篇 ID 写入 `aweme_id.txt`（抖音 `aweme_id` / 小红书 `note_id` / 微博 `mblog_id`）。

分工边界：

| 层 | 负责 |
|---|---|
| 平台 `scrape_stream()` | 登录闸门、页面级身份获取与上报、条目发现与归一化、作者过滤；不再返回全量结果 |
| `core/session.py` | 冻结身份与已下载 ID 查询、逐篇调度、无时间/无媒体/失败统计、取消检查、收口 |
| `core/downloader.py` | `fetch_article` 复用 `fetch_all` 做重试与扩展名探测、批量并发、按篇聚合写 ID；落盘路径向 `store` 要，不拼目录 |
| `core/task.py` | 维护日志、失败清单、取消状态；`stream` 只记日志，`finished` 一次性写收口统计 |
| `core/pipeline.py` | 串联流式会话，处理取消与「没有可下载内容」的收尾 |

#### 不显示进度条，快照统计字段仅用于收口汇总

界面不渲染进度条，也不显示百分比与 `done/total` 文本。`done` / `total` / `percent` 仍保留在任务快照里（API 兼容），但只在任务收口时由一次 `finished` 事件写入：`done` = 成功文件数，`total` = 本次处理文件数，`percent` 由两者算一次；不再有逐文件的进度上报与刷新。日志仍保留每个媒体一条「正在下载 xxx」，失败条目进失败清单。

- 已下载的篇由 `session.meta()` 返回的 `known_ids` 与下载层按篇 ID 统一校验、直接排除，不计入本次处理数
- 一篇内的多个媒体仍属于同一篇；去重与断点续传按篇粒度：一个下载单元一个 ID，全部成功才记录
- **新增平台必须遵守**：实现 `scrape_stream()`，从页面取身份后先 `session.meta()`，再逐条 `session.article()`；**不要给下载层传博主对象或任何目录**——落盘路径由 `store` 的当前任务目标给出。命名、扩展名探测、去重校验都由下载层负责，平台只管归一化条目，不要自己维护 `done` / `total`；平台层不出现任何路径拼接

#### ID 记录约定：一篇一个 ID，全部成功才记录

断点续传与去重共用一个粒度：`{博主目录}/aweme_id.txt` 里一行一个篇 ID（文件名沿用历史命名，三个平台通用，内容分别为抖音 `aweme_id` / 小红书 `note_id` / 微博 `mblog_id`）。

- 一篇内的全部媒体都下载成功，才在篇完成时写入该篇 ID；任一张失败或没有可用地址，整篇都不记录
- 下载前先把记录读成内存 `set`，由 `session.meta()` 与下载层统一校验；篇 ID 已存在就整篇排除（不计入本次处理数）
- 上次部分失败的篇不会留下半篇记录，下次整篇重下（同名文件覆盖），保证「有记录 = 这一篇完整」
- ID 攒够 20 个批量追加一次，任务结束或取消时再补写一次；读取时忽略空行，不依赖文件顺序
- **新增平台必须遵守**：一篇一个 ID、全部成功才记录，不要按单张图片或单个 URL 记录

#### 下载日志约定：每地址一条「正在下载 xxx」

下载阶段的日志由 `core/downloader.py` 统一输出，每个地址开始下载时打一条 `正在下载 {文件名}`：

- 任务开始逐篇处理时，由公用层统一打印 `开始下载 {平台显示名} <{博主名}>`（独立 `notice` 事件），平台实现不用自己打
- 拿到响应头后即打印日志：响应头或 URL 能确定扩展名时显示最终文件名，否则显示 `{发布时间} - {序号}.part` 临时名（下载时扩展名未定，先落 `.part`，完成后再按扩展名决定落盘目录与最终文件名）
- 一篇里有几个媒体就打几条，按地址粒度；跳过或取消的地址不打这条
- 新增平台不用自己打下载日志，交给 `fetch_all` 的 `log` 回调即可

### 新增平台步骤

1. 在 `platforms/<key>/` 下实现 `scraper.py`（登录闸门 + 翻页/详情发现 + 页面级身份获取）与 `assemble.py`（条目归一化函数）
2. 新建 `platforms/<key>/__init__.py`，继承 `platforms/base.py` 的 `Platform`，声明 `key`、`label`、`media_label` 并实现 `match` / `parse_target` / `scrape_stream`（内部先 `session.meta()` 上报身份，再逐条 `session.article()`），不再实现 `scrape` / `assemble`
3. 在 `platforms/__init__.py` 中 `import` 并 `registry.register(...)`；前端平台下拉框与博主分组会自动出现，无需改前端
4. 登录态目录默认落在 `.pw_profile/<key>`，无需额外配置；需要专属下载头时实现 `headers()`，需要落盘后处理时实现 `post_process()`
5. 需要支持「关注列表」时再实现 `following()` 与 `user_id_of()`，并把 `supports_following` 置为 `True`；路由与前端按钮会自动出现（可选）

## Web API

界面全部通过以下本地接口工作（仅供本机使用）：

| 方法 | 路径 | 说明 |
|---|---|---|
| `GET` | `/` | 首页；按静态资源内容注入版本号与配置里的标题 |
| `GET` | `/api/status` | 博主总数、当前任务快照、Playwright 是否可用、已注册平台列表 |
| `POST` | `/api/scrape` | 提交一个链接抓取并下载；`range` 为 `all` / `month` |
| `POST` | `/api/following` | 读取本机登录账号的关注列表（`platform`，当前仅 `douyin`）；只返回清单，不触发下载 |
| `GET` | `/api/tasks/<task_id>` | 任务快照（阶段/状态、日志、失败列表；含仅用于汇总的 done/total/percent） |
| `POST` | `/api/tasks/<task_id>/cancel` | 取消任务 |
| `GET` | `/api/bloggers` | 按平台分组返回博主列表与主页链接 |
| `POST` | `/api/bloggers/<platform>/<name>/update` | 用 `homepage.txt` 重新抓取，按 ID 只补新增 |
| `DELETE` | `/api/bloggers/<platform>/<name>` | 删除博主目录（含 `.cache`）；任务进行中拒绝 |
| `GET` | `/api/bloggers/<platform>/<name>/files` | 博主目录下的图片 / 视频清单（含缩略图与封面地址） |
| `POST` | `/api/covers` | 前端回存视频首帧封面（`platform` / `name` / `path` / `data:image/...`，上限 512KB） |
| `GET` | `/api/media?path=&thumb=&platform=&name=` | 媒体文件响应，支持区间读取；图片可带 `thumb` 走缩略图，缓存位置由 `platform` / `name` 确定 |

- 最近 20 个任务快照会保留在内存中，过期返回 404
- 缩略图与封面 URL 带文件修改时间版本号，可按内容长期缓存；其他静态资源与媒体默认每次回源校验
- 媒体路径只接受下载根目录内的相对路径，越界或不存在一律 404

## 常见问题排查

| 现象 | 处理 |
|---|---|
| 「下载」按钮灰色 | 未安装 Playwright：`pip install playwright` 与 `playwright install chromium` 后重启；关注模式下还没勾选博主时也是灰色 |
| 提示未登录 / 只抓到少量内容 | 把对应平台段的 `headless` 设为 `false`，重启后在弹出的浏览器窗口扫码 |
| 点「获取我的关注」提示未登录 | 关注列表只有登录后才可见：把对应平台段的 `headless` 改为 `false`，重启后扫码 |
| 「获取我的关注」按钮灰色 | 没有平台支持关注列表（当前仅抖音），或已有任务在执行；也可先确认 Playwright 已安装 |
| 小红书笔记打不开详情 | 主页链接的 `xsec_token` 已过期，重新复制主页链接抓取一次 |
| 微博图片全部下载失败（403） | 把 `[platforms.weibo] referer` 改成 `https://weibo.com/` |
| 下载到一半被限流、大量失败 | 把 `[download] workers` 调小（`1` 即逐个下载） |
| 抓取条数明显偏少 | 确认已登录；适当调大 `max_scroll`；微博会按翻页上限提前结束并提示 |
| 提示「没有可下载内容」 | 已全部下载过、未登录、所选时间范围内无作品，或该主页没有公开作品 |
| 博主列表看不到某个目录 | 博主需位于 `{download_dir}/{平台 key}/` 下，且含 `homepage.txt`、`picture/` 或有视频文件 |
| 升级后旧目录不见了 | 把 `download_dir` 末尾的平台目录去掉一级（如 `F:/图片/douyin/` → `F:/图片/`） |
| 预览缩略图异常 | 删除博主目录下的 `.cache/` 后刷新，缓存会自动重建 |

## 注意事项

1. **文件编码**：`homepage.txt`、`aweme_id.txt` 均按 UTF-8 读写
2. **数据时效性**：平台接口数据具有时效性，建议抓取后尽快完成下载
3. **登录状态**：确保对应平台账号已登录（首次需在自动弹出的窗口里扫码），否则可能无法获取完整数据
4. **下载频率**：默认逐个下载；开启并发后被 CDN 限流时把 `workers` 调小，避免触发风控
5. **存储空间**：视频文件较大，请确保目标磁盘空间充足
